Red-team round 4 — ATTEMPTS
===========================
Independent attacker. Target: an untrusted container (compiled --untrusted,
shipped certificate, verified at install, run on the Rust core with the
reduced primitive set). New surface since round 3: trusted containers on the
same loop with trusted-only unchecked twins (104..113) and builtins (101..103),
format 2 as host default (--untrusted selects checked compilation), the verdict
flag bound by the header CRC, 16-byte method records, the new `needed` stack
bound, shared primitive argument decoders.

Builds: build/host (64-bit release, verified core), build/host32 (32-bit
release), build/asan (-fsanitize=address,undefined, TOIT_DEBUG asserts).
Benign sanitizer noise filtered everywhere: gc_metadata.h:360 (GC-class dartino
misaligned uword load/store, fires on trusted hello world too — excluded from
the claim) and the format-1 primitive.h null-member-call UBSan line.

One line per attempt: id | idea | command/battery | observed result.
Per-case detail is in review/red-team/round4/repro/<line>-results.txt.

VERDICT: no memory-safety, isolation, DoS or policy breach found. One LOW
spec-vs-code / UB finding (F-TIMEINFO). The strongest ideas (twin smuggling,
certificate forgery, 32/64 divergence, crafted collections into C++ primitives)
were all stopped by a named verifier rule, the certificate soundness proof, the
loader bounds, or the always-on run-time checks.

C. 32-bit vs 64-bit differential (minimum 30 programs + >=2h fuzz) — 31 programs + fuzz
================================================================
review/red-team/round4/battery-C.sh -> repro/C-results.txt
 31 crafted programs (repro/cedges/*.toit) around word-size edges: smi 2^30/2^62
 boundaries, large-int arithmetic/shifts/div/mod, to-float/to-int, int/str/ba
 hashing, large array/byte-array lengths, slices, Map/Set sizes to several
 thousand, int.parse, count-trailing-zeros, large bitops, stack depth, graceful
 stack overflow. Each compiled --untrusted once, run on host (64) and host32 (32).
 Result: all 31 byte-identical, same exit code, no crash/sanitizer.
C-note-1 (benign/expected divergence): deep recursion. At depth 500 the 64-bit
 build reports a graceful STACK_OVERFLOW at ~497 frames while the 32-bit build
 completes — 8-byte frames fill the fixed byte-capacity stack sooner than 4-byte
 frames. Both are safe (graceful, no crash); the control-flow difference is the
 unavoidable word-size effect on frame count, not a soundness bug. The battery
 uses depth 150 (both complete) and a catch-wrapped huge recursion that both
 report as STACK_OVERFLOW identically.
Differential fuzz (>=2h): /home/flo/work/opentoit-sandbox-artifacts/red-team-4/difffuzz.sh
 Mutates 1..6 bytes (back 70%) of untrusted snapshots from a 5-program corpus,
 runs each on host64 and host32 --untrusted, flags crash/sanitizer on either or a
 divergence in exit code or address-normalized output. ~11 mutants/s.
 Result (difffuzz/log.txt): 125,702 mutants in 7,500 s (2h05m), 0 findings
 (no crash, no exit-code or output divergence). Caveat: byte mutations are
 mostly rejected identically by the loader/verifier, so this run mainly hunts
 crashes in the loader, verifier and certificate paths. It explores few
 runnable divergent programs; the 31 crafted programs above cover those.

** FINDING F-TIMEINFO (LOW: spec-vs-code / UB, no memory unsafety, no breach) **
 f18-timeinfo-ext | time_info with an extreme int64 timestamp | repro/timeinfo-overflow.toit
 utc_fields (src/primitive_core.cc:1243-1244) computes
   days = floor_div(timestamp, SECONDS_PER_DAY);
   seconds_of_day = timestamp - days * SECONDS_PER_DAY;
 For a timestamp near INT64_MIN/MAX, `days * SECONDS_PER_DAY` and the subtraction
 overflow a signed int64 -> UBSan: "signed integer overflow: -106751991167301 *
 86400 ...". The overflow happens BEFORE the Smi::is_valid32(year) range check.
 Reachable by an UNTRUSTED container through a DIRECT time_info primitive call
 (time_info is in the allowed set, C++, not a Rust port; an untrusted program can
 declare #primitive.core.time_info and pass any int64). The public Time.utc /
 Time.local wrapper caps the seconds via its microsecond conversion and does NOT
 reach the overflow boundary — so the finding needs a raw primitive call.
 RELEASE host64 behaviour: throws OUT_OF_RANGE, no wrong value escapes, ASan
 reports no memory error -> benign on two's-complement, but it is undefined
 behaviour a compiler may optimise on. The primitive audit lists time_info as
 "fixed/OK"; this overflow path was missed. Fix belongs to others (clamp/guard
 the timestamp before the multiply, as the integer primitives were guarded in
 round 1). Battery-F whitelists primitive_core.cc:124x so it stays green while
 recording the finding.
