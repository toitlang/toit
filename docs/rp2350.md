# RP2350

The port targets the WeAct RP2350B Core Board with 16 MiB flash, using the
RP2350 Arm Secure platform (`rp2350-arm-s`). RP2040 and RISC-V builds are not
supported. Peripheral APIs take GPIO numbers: GP40 is `40`, independent of its
physical header position. Passing a `gpio.Pin` to configure another peripheral
is not supported.

## Building

Install an Arm GNU `arm-none-eabi` toolchain with newlib and C++ libraries,
plus the normal host Toit build dependencies, CMake, Ninja, pkg-config and
libusb development files. Then run from the repository root:

```sh
make rp2350-setup
make rp2350-envelope RP2350_VERSION=1
```

The Pico SDK lives in the pinned `third_party/pico-sdk` submodule. Setup
initializes its dependencies and builds picotool in `.cache/rp2350`; it does
not flash a board or install system files. The compiler is not pinned. Select
a different installed compiler with
`RP2350_CMAKE_FLAGS='-DPICO_TOOLCHAIN_PATH=/path/to/toolchain'`, using a fresh
build directory when switching compilers.

The output envelope is `build/rp2350-envelope/firmware.envelope`. It initially
contains the system container. Install an application boot container that
checks startup health and calls `system.firmware.validate` before using it for
an update. The system container deliberately does not confirm trial firmware
on the application's behalf.

Use the [firmware bundle instructions](rp2350-envelope-bundle.md) to flash an
envelope. The [update design](rp2350-ota.md) describes rollback, the flash
layout, and the distinction between recovery images and trial updates.

## Runtime and peripherals

The VM runs on core 0 under FreeRTOS. GPIO, UART, I2C and SPI events share one
event task; interrupt handlers retain pending resource state and wake the
dispatcher. Core 1 is unused. Using it would require coordination around flash
operations while XIP is unavailable.

The port provides GPIO, ADC, PWM, UART, I2C controller and target, and SPI
controller and target support. SPI controllers support all four modes. SPI
targets support modes 1 and 3; modes 0 and 2 require chip-select pulses between
frames on this hardware and are rejected. I2C address-only probing and bus
scanning remain TODO; a future GPIO implementation must preserve bus pin
ownership and restore the peripheral function afterward.

The port includes the standard firmware service, persistent flash registry,
containers, assets and configuration, timed deep sleep, a shared
`system.watchdog` API, and native failure recovery. TLS clients support
session export and Toit's encrypted-record implementation, exercised over
UART by the hardware tests. The port has no network transport.

Hardware wiring, test selection and execution are documented beside the
[hardware tests](../tests/hw/rp2350/README.md). Host-only image and layout checks
are in [tools/rp2350/tests](../tools/rp2350/tests/README.md).
